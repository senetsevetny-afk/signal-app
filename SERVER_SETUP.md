# Сервер доступа — как запустить

Сервер решает то, что нельзя решать в браузере: срок пробного доступа,
выдачу PRO за приглашения и защиту от накрутки. Он живёт в том же процессе,
что и бот, и поднимается автоматически.

## Что загрузить в репозиторий бота
```
bot.py
requirements.txt
Procfile
server/__init__.py
server/access.py
cards/about.png
```

## Переменные окружения
| Имя | Значение | Обязательна |
|---|---|---|
| TG_TOKEN | токен от @BotFather | да |
| APP_URL | ссылка на мини-приложение | да |
| PORT | порт HTTP, хостинг обычно задаёт сам | нет |
| DB_PATH | файл базы, по умолчанию market_ai.db | нет |
| TRIAL_HOURS | длительность пробного доступа, по умолчанию 32 | нет |
| REF_DAYS | дней PRO за приглашение, по умолчанию 7 | нет |
| REF_NEEDED | сколько приглашённых нужно для награды, по умолчанию 1 | нет |
| TD_KEY | резервный ключ котировок | нет |

## Проверка
Откройте в браузере `https://ваш-сервер/api/health` — должен вернуться
`{"ok": true, ...}`.

## Подключение приложения
Профиль → раздел «Доступ» → «Указать адрес сервера» → вставьте адрес
без завершающего слэша. Приложение запомнит его и начнёт спрашивать
состояние доступа у сервера.

## Как это защищено
Каждый запрос несёт initData из Telegram WebApp. Сервер проверяет подпись
по HMAC с токеном бота и отклоняет всё, что не подписано. Идентификатор
пользователя приходит из подписанных данных, подделать его нельзя.

Приглашение засчитывается не сразу: приглашённый должен реально
пользоваться приложением хотя бы час с первого входа. Приглашение самого
себя и ссылки на несуществующих пользователей отклоняются.

## Важное ограничение
Пока сервер не подключён, приложение честно пишет об этом и работает
без ограничений. Рисовать таймер пробного периода в браузере нельзя:
он стирается очисткой хранилища за секунду и вводил бы в заблуждение.
